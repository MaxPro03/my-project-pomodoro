# Apelsini

8-bit pomodoro timer where every finished focus session grows an orange.
Nuxt 4 app: the client (SPA + PWA) and the API (Nitro + Prisma + PostgreSQL) live in one project.

Needs Node `^22.22.3 || ^24.15.0 || >=26` (see `.nvmrc`).

```sh
cp .env.example .env   # DATABASE_URL; NUXT_SESSION_PASSWORD is generated by nuxt dev if empty
npm install            # also generates the Prisma client and Nuxt types
npm run db:migrate     # create / update the tables (prisma migrate dev)
npm run dev            # http://localhost:3000, add ?fast to shorten phases to seconds
npm run build          # .output/, run with node .output/server/index.mjs
```

The timer itself works without a database; only login, sync and stats need one.

## Structure (FEOD)

The project follows [FEOD](https://feod.dev/) — Fractal Entity Oriented Design.
Imports only go one way: `common → modules → pages → app`. Modules are used only through their `index.js`;
`common` has no index files. Nuxt auto-imports from our folders are off, everything is imported explicitly.

```
nuxt.config.js  Nuxt, PWA, head, session cookie
src/
  app.vue     root component (Nuxt requires it here)
  app/        styles, integrations/ (Nuxt plugins: pinia, backend wiring), assets/
  pages/      index.vue — the only screen for now
  modules/
    Pomodoro/ timer logic, settings and the game screen
    Orange/   the 3D mascot, pixel sprites and harvest crates
    Auth/     registration and login (no UI on the page yet)
    Stats/    session history and statistics (no UI on the page yet)
  common/
    ui/         PixelButton, PixelSprite
    utilities/  sfx (chiptune sounds), http ($fetch preset for /api)
server/       the API (Nitro), see server/README.md
prisma/       schema and migrations
```

## Deploy (Vercel + Neon)

1. Create a Neon database and import the repo in Vercel (it detects Nuxt, no config needed).
2. Vercel env: `DATABASE_URL` (Neon pooled string), `DIRECT_URL` (Neon direct string), `NUXT_SESSION_PASSWORD`
   (32+ chars, `openssl rand -hex 32`).
3. Apply migrations: `npm run db:deploy` with those env vars, or set the Vercel build command to
   `npm run db:deploy && npm run build`.
